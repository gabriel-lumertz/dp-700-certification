Ao monitorar superfícies alterando dados, anomalias ou eventos críticos, os alertas são gerados ou as ações são disparadas. A análise de dados em tempo real geralmente se baseia na ingestão e no processamento de um fluxo de dados que consiste em uma série perpétua de dados, normalmente relacionada a eventos pontuais específicos. Por exemplo, um fluxo de dados de um sensor meteorológico de IoT ambiental. Real-Time Intelligence in Fabric contém uma ferramenta chamada Activator que pode ser usada para disparar ações em dados de streaming. Por exemplo, um fluxo de dados de um sensor meteorológico de IoT ambiental pode ser usado para disparar e-mails para marinheiros quando os limites de vento são atingidos. Quando determinadas condições ou regras lógicas são atendidas, uma ação é tomada, como alertar os usuários, executar itens de trabalho do Fabric, como pipelines, ou iniciar fluxos de trabalho do Power Automate. A lógica pode ser um limite definido, um padrão como eventos acontecendo repetidamente durante um período de tempo ou os resultados da lógica definida por uma consulta KQL (Kusto Query Language).

## O que é o Ativador

O Activator é uma tecnologia do Microsoft Fabric que permite o processamento automatizado de eventos que disparam ações. Por exemplo, você pode usar o Activator para ser notificado por email quando um valor em um fluxo de eventos se desvia de um intervalo específico ou executar um notebook para realizar algumas lógicas de processamento de dados baseada no Spark quando um painel de controle em tempo real for atualizado.

## Entenda os principais conceitos do Activator

O Activator opera com base em quatro conceitos principais: _Eventos_, *Objetos, _Propriedades_ e _Regras_.

- **Eventos** – cada registro em um fluxo de dados representa um _evento_ que ocorreu em um ponto específico no tempo.
- Objetos – Os dados em um registro de evento podem ser **usados** para representar um _objeto_, como um pedido de vendas, um sensor ou alguma outra entidade de negócios.
- **Propriedades** – Os campos nos dados de evento podem ser mapeados para _propriedades_ do objeto de negócios, representando algum aspecto de seu estado. Por exemplo, um campo _total_amount_ pode representar um total de pedidos de _vendas_ ou um campo de temperatura pode representar a temperatura medida por um sensor ambiental.
- **Regras** – A chave para usar o Activator para automatizar ações com base em eventos é definir _regras_ que definem condições sob as quais uma ação é disparada com base nos valores de propriedade de objetos referenciados em eventos. Por exemplo, você pode definir uma regra que envie um email para um gerenciador de manutenção se a temperatura medida por um sensor exceder um limite específico.

## Casos de uso do Activator

O Activator pode ajudar você em vários cenários, como, por exemplo, gerenciamento dinâmico de estoques, interação com o cliente em tempo real e alocação eficaz de recursos em ambientes de nuvem. É uma ferramenta potente para qualquer circunstância que requeira análise de dados e ações em tempo real.

Use o Activator para:

- Iniciar ações de marketing quando as vendas de produtos caírem.
- Enviar notificações quando mudanças de temperatura puderem afetar produtos perecíveis.
- Sinalizar problemas em tempo real que afetam a experiência do usuário em aplicativos e sites.
- Disparar alertas quando uma remessa não tiver sido atualizada dentro de um período esperado.
- Enviar alertas quando o saldo da conta de um cliente ultrapassar um determinado limite.
- Responder a anomalias ou falhas nos fluxos de trabalho de processamento de dados imediatamente.
- Execute anúncios quando as vendas da mesma loja diminuírem.
- Alertar os gerentes da loja para mover alimentos de freezers de supermercados com defeitos antes que eles estraguem.
