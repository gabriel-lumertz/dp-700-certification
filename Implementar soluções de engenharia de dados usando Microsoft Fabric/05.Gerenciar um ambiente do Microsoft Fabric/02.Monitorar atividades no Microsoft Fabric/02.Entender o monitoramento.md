O monitoramento é o processo de coleta de dados e métricas do sistema que determinam se um sistema está íntegro e funcionando conforme o esperado. O monitoramento expõe erros ocorridos e quando eles ocorreram. Para investigar problemas e corrigir erros, os dados históricos são analisados para obter uma imagem da integridade de um sistema ou processo.

## Monitorando atividades do Fabric

No Fabric, você agenda atividades e trabalhos que executam tarefas como movimentação de dados e transformação. As atividades têm dependências umas das outras. Você precisa garantir que os dados cheguem ao local esperado a tempo e que erros ou atrasos do sistema não afetem usuários ou atividades downstream. Os processos de ponta a ponta precisam ser gerenciados para garantir que sejam confiáveis, com desempenho e resilientes. Um aspecto desse monitoramento é identificar e lidar com operações de execução longa e erros efetivamente. Ao fazer isso, você pode minimizar o tempo de inatividade e resolver rapidamente quaisquer problemas subjacentes.

As atividades a seguir no Fabric permitem que você execute tarefas que fornecem dados aos usuários. Essas atividades devem ser monitoradas:

- **Atividade do pipeline** de dados – um pipeline de dados é um grupo de atividades que, juntas, executam uma tarefa de ingestão de dados. Os pipelines permitem que você gerencie, extraia, transforme e carregue atividades (ETL) em conjunto em vez de individualmente. Monitore o êxito ou a falha de trabalhos e atividades de pipeline. Procure erros se o pipeline falhou. Exiba o histórico de trabalhos para comparar o desempenho da atividade atual com o desempenho de execução do trabalho anterior para obter informações sobre quando os erros foram introduzidos pela primeira vez em um processo.

- **Fluxos de** dados – um fluxo de dados é uma ferramenta para ingerir, carregar e transformar dados usando uma interface de baixo código. Os fluxos de dados podem ser executados manualmente ou agendados ou executados como parte da orquestração de pipeline. Monitore os horários de início e término, status, duração e atividades de carregamento da tabela. Para investigar problemas, faça drill down das atividades e exiba informações sobre erros.

- **Atualizações semânticas de modelo** – um modelo semântico é uma representação visual de um modelo de dados que está pronto para relatórios e visualização. Ele contém transformações, cálculos e relações de dados. As alterações no modelo de dados exigem que o modelo semântico seja atualizado. Modelos semânticos podem ser atualizados de pipelines de dados usando a atividade _de atualização semântica do modelo_ . Monitore as novas tentativas de atualização para ajudar a identificar problemas transitórios, antes de classificar um problema como uma falha.

- **Trabalhos do Spark, notebooks e lakehouses – notebooks** são uma interface para desenvolver trabalhos do Apache Spark. Os dados podem ser carregados ou transformados para lakehouses usando Spark e notebooks. Monitore o progresso do trabalho do Spark, a execução da tarefa, o uso de recursos e examine os logs do Spark.

- **Fluxos de eventos do Microsoft Fabric** – Os eventos são observações sobre o estado de um objeto, como um carimbo de data/hora para sensores meteorológicos. Os fluxos de eventos no Fabric são configurados para serem executados perpetuamente para ingerir eventos em tempo real ou streaming no Fabric e transformá-los para necessidades de análise e, em seguida, roteá-los para vários destinos. Monitore dados de eventos de streaming, status de ingestão e desempenho de ingestão.


## Melhores práticas de monitoramento

Monitore continuamente os processos de ingestão, transformação e carregamento de dados para garantir que eles estejam funcionando sem problemas. As práticas recomendadas de monitoramento incluem:

- **Identificando o que monitorar** e acompanhar as métricas.
- **Coletando e analisando dados regularmente** para identificar o comportamento normal para que você possa detectar anomalias quando elas ocorrerem.
- **Revisar logs e métricas regularmente** para identificar e estabelecer parâmetros para o comportamento normal do sistema.
- **Tomando medidas** para resolver problemas quando as métricas e os logs mostram desvios do comportamento normal.
- **Otimizando o desempenho** usando dados de monitoramento para identificar gargalos ou problemas de desempenho.
