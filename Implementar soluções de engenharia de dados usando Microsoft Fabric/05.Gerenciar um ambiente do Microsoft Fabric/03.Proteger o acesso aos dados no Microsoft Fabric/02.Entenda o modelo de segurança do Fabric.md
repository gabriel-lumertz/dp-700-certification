O acesso a dados em organizações geralmente é restringido pelas responsabilidades e funções dos usuários, pelos padrões de implantação do Fabric de uma organização e pela arquitetura de dados. O Fabric tem um modelo de segurança flexível de várias camadas que permite configurar a segurança para acomodar diferentes requisitos de acesso a dados. Ter a capacidade de controlar permissões em diferentes camadas significa que você pode aderir ao princípio de privilégios mínimos, restringindo as permissões de usuário apenas ao que é necessário para executar tarefas de trabalho.

O Fabric tem três níveis de segurança e eles são avaliados sequencialmente para determinar se um usuário tem acesso a dados. A ordem de avaliação para acesso é:

1. Autenticação do Microsoft Entra ID: verifica se o usuário pode se autenticar no serviço de gerenciamento de identidade e acesso do Azure, o Microsoft Entra ID.
2. Acesso ao Fabric: verifica se o usuário pode acessar o Fabric.
3. Segurança de dados: verifica se o usuário pode executar a ação solicitada em uma tabela ou arquivo.

O terceiro nível, a segurança de dados, tem vários blocos de construção que podem ser configurados individualmente ou em conjunto para se alinhar com diferentes requisitos de acesso. Os principais controles de acesso no Fabric são:

- Funções do espaço de trabalho
- Permissões de item
- Permissões de computação ou granulares
- Controles de acesso a dados do OneLake (versão prévia)

É útil imaginar esses blocos de construção em uma hierarquia para entender como os controles de acesso podem ser aplicados individualmente ou em conjunto.

Um _workspace_ no Fabric permite distribuir políticas de propriedade e acesso usando _funções de workspace_. Em um workspace, você pode criar _itens_ de dados do Fabric, como lakehouses, data warehouses e modelos semânticos. As _permissões de item_ podem ser herdadas de uma função de workspace ou definidas individualmente compartilhando um item. Quando as funções do espaço de trabalho fornecem muito acesso, os itens podem ser compartilhados usando permissões de item para garantir a segurança adequada.

Em cada item de dados, _permissões granulares do mecanismo_, como Read, ReadData ou ReadAll, podem ser aplicadas.

Permissões de computação ou granulares podem ser aplicadas em um mecanismo de computação específico no Fabric, como o Ponto de Extremidade do SQL ou o modelo semântico.

Os itens de dados do Fabric armazenam seus dados no OneLake. O acesso aos dados no lakehouse pode ser restrito a arquivos ou pastas específicos usando o recurso RBAC (controle de acesso baseado em função) chamado controles de acesso a dados do OneLake (versão prévia).
