Uma arquitetura de medalhão cria um limite de controle de acesso natural: diferentes equipes precisam de camadas diferentes. Engenheiros de dados trabalham em bronze e prata; os analistas e os usuários empresariais consomem ouro. Impor esses limites requer uma abordagem deliberada para permissões e gerenciamento de alterações.

## Controlar o acesso por camada

Fabric fornece dois níveis de controle de acesso.

**As permissões do espaço de trabalho e dos itens** controlam quem pode ver e interagir com itens do Fabric em um espaço de trabalho. As funções de workspace (Administrador, Membro, Colaborador, Visualizador) se aplicam a tudo nesse workspace. As permissões de item são mais granulares — você pode compartilhar um lakehouse específico com um colega sem conceder a ele acesso a todo o espaço de trabalho.

Para um maior isolamento entre camadas, você pode colocar cada camada medallion em um espaço de trabalho separado. Isso fornece a cada camada sua própria capacidade, suas próprias atribuições de função e um limite de propriedade claro. A desvantagem é ter mais espaços de trabalho para gerenciar.

**As funções de acesso a dados do OneLake** oferecem controle granular em um único lakehouse, sem a necessidade de workspaces separados. Você pode definir um escopo de uma função para tabelas ou pastas específicas, para que um consumidor de camada de ouro possa consultar tabelas de ouro, mas não pode ver bronze ou prata. Cada lakehouse vem com uma função interna `DefaultReader` que concede a todos os usuários do ReadAll acesso a todos os dados; modifique ou exclua-os para restringir o acesso padrão.

Para configurar a segurança do OneLake, abra o lakehouse e **selecione Gerenciar a segurança do OneLake**. A partir daí, crie uma função, defina seu escopo e atribua membros.

|Approach|Quando usar|
|---|---|
|Funções de acesso a dados do OneLake|Equipes que compartilham um espaço de trabalho e precisam de níveis de acesso à tabela diferentes em cada camada|
|Espaços de trabalho separados por camada|Isolamento forte, limites de conformidade ou capacidade separada necessária|

## Gerenciar a alteração com o Git

Uma arquitetura de medalhão envolve código: definições de pipeline, transformações de notebook e definições de esquema que precisam permanecer em sincronia. Sem o controle de versão, uma implantação incorreta pode corromper dados no meio da camada sem uma maneira fácil de recuperar.

A integração com Git do Fabric conecta seu workspace a um repositório Git, de modo que seus notebooks, pipelines e definições de lakehouse sejam versionados em conjunto. Se uma mudança em uma transformação comprometer a camada silver, você poderá reverter para o commit anterior. As equipes podem trabalhar em ramificações e mesclar alterações por meio de um processo de pull request — o mesmo fluxo de trabalho usado para código de aplicativo.

Os pipelines de implantação ampliam isso ainda mais: você pode promover seu workspace medallion de desenvolvimento para teste e, depois, para produção em uma sequência controlada, com a capacidade de comparar ambientes e identificar diferenças antes que afetem os dados de produção.
