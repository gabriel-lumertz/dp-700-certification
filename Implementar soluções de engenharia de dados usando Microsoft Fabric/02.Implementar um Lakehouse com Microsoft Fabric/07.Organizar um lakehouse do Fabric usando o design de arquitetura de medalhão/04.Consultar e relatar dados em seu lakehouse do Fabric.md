Com dados organizados e refinados em camadas bronze, prata e ouro, a etapa final é torná-los acessíveis para consultas e relatórios. A camada de ouro é criada para isso – é onde os engenheiros de dados já fizeram o trabalho de modelagem para que analistas e usuários de negócios possam obter respostas sem pesquisar dados brutos.

## Consultar os dados com o endpoint de análise SQL

O endpoint de análise SQL no Fabric concede a qualquer membro da equipe com conhecimento em SQL acesso direto à camada gold. Você pode escrever consultas T-SQL, salvar funções, gerar exibições e aplicar a segurança do SQL , tudo sem mover dados ou criar uma camada de consulta separada.

O endpoint de análise SQL opera em modo **somente leitura** em tabelas Delta do lakehouse.

## Fornecer dados por meio de um modelo semântico Power BI

Para usuários Power BI, a camada de ouro é exibida por meio de um **modelo semântico**. Para criar um, selecione **Novo modelo semântico** na lakehouse e escolha quais tabelas de camadas de ouro incluir. Power BI relatórios se conectam ao modelo semântico, não diretamente às tabelas Delta brutas.

[![Captura de tela de um modelo semântico Power BI mostrando tabelas de camadas de ouro com relações definidas entre uma tabela de fatos e tabelas de dimensão.](https://learn.microsoft.com/pt-br/training/wwl/describe-medallion-architecture/media/dataset-relationships.png)](https://learn.microsoft.com/pt-br/training/wwl/describe-medallion-architecture/media/dataset-relationships.png#lightbox)

Modelos semânticos se conectam à camada gold usando o modo **Direct Lake**. O Direct Lake lê diretamente dos arquivos Delta no OneLake em vez de importar uma cópia para Power BI. Os relatórios sempre mostram dados atuais sem uma etapa de atualização separada.
