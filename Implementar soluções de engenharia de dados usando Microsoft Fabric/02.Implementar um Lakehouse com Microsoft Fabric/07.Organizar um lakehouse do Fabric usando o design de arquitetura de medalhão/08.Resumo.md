A **arquitetura do medalhão** organiza um Fabric lakehouse em três camadas progressivas. A **camada de bronze** preserva os dados brutos exatamente conforme chegam — uma fonte permanente da verdade a partir da qual você sempre pode reprocessar os dados. A **camada prata** limpa e integra esses dados: padronizando formatos, removendo nulos, eliminando duplicação e unindo fontes em um conjunto de dados confiável. A **camada de ouro** modela dados para consumo, moldados para o público específico, seja um esquema em estrela para relatórios, uma tabela desnormalizada para ciência de dados ou resumos pré-agregados para uma equipe de negócio.

Ao planejar a implementação em Fabric, você estrutura sua lakehouse usando esquemas — `bronze``silver`e `gold` — que mantêm as tabelas organizadas e permitem que você defina diferentes permissões de acesso por camada. Para ingestão em bronze, os atalhos do OneLake permitem que você faça referência aos dados de armazenamento em nuvem no local sem copiar; pipelines, fluxos de dados e notebooks lidam com outras fontes. Para transformações silver e gold, você escolhe com base na complexidade: fluxos de dados para tarefas simples com pouco código, notebooks para lógica personalizada e visões materializadas do lake quando a transformação pode ser expressa em SQL e você quer que o Fabric gerencie a atualização incremental automaticamente.

Os dados da camada Gold são disponibilizados de duas maneiras: por meio do endpoint de análise SQL, para quem deseja escrever T-SQL diretamente, e por meio de um modelo semântico do Power BI, para criadores de relatórios. Modelos semânticos usam o modo Direct Lake, que lê diretamente de arquivos Delta no OneLake para que os relatórios permaneçam atualizados sem uma etapa de atualização separada.

Proteger uma arquitetura medallion significa alinhar os limites de acesso à responsabilidade de cada camada. As funções de acesso a dados do OneLake permitem definir o escopo das permissões para tabelas específicas em um lakehouse compartilhado, de modo que os consumidores da camada dourada não possam ver dados das camadas bronze ou prata. Para um isolamento mais rigoroso, espaços de trabalho separados fornecem a cada camada sua própria capacidade e atribuições de funções. A integração com o Git mantém versionados juntos o código do seu pipeline, os notebooks e as definições de esquema — assim, uma implantação malsucedida pode ser revertida, e as alterações podem ser promovidas de desenvolvimento para produção por meio de pipelines de implantação.

Pronto para criar o seu próprio? Comece [criando um Fabric lakehouse](https://learn.microsoft.com/pt-br/fabric/onelake/create-lakehouse-onelake) e configurando seus esquemas de bronze, prata e ouro.
