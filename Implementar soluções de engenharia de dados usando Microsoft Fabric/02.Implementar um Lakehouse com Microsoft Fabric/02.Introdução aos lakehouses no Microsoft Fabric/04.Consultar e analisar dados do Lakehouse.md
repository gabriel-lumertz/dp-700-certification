Depois de ingerir e transformar dados, ele estará pronto para análise. Um Lakehouse no Microsoft Fabric oferece diversas maneiras de consultar e analisar dados, permitindo que você escolha a ferramenta certa para cada tarefa. Se você preferir SQL para padrões de consulta familiares ou Spark para análise complexa, o lakehouse acomoda seu fluxo de trabalho.

## Consultar dados usando o endpoint de análise SQL

O ponto de extremidade de análise de SQL fornece acesso somente leitura a tabelas do lakehouse usando consultas T-SQL. Esse ponto de extremidade é criado automaticamente junto a cada lakehouse. Ele permite que você consulte tabelas sem afetar os arquivos de dados subjacentes. Você pode escrever consultas para explorar dados, filtrar linhas, agregar valores e unir tabelas, assim como faria com um banco de dados SQL tradicional.

Os casos de uso comuns para o endpoint de análises SQL incluem:

- **Consultas ad hoc**: investigue rapidamente os dados para responder a perguntas comerciais.
- Conexões de inteligência de negócios: Ferramentas como Power BI, Excel ou Azure Data Studio podem ser conectadas para recuperar dados para relatórios.
- **Validação de dados**: verifique os resultados da transformação depois de carregar ou processar dados.

Você também pode criar exibições SQL para armazenar a lógica de consulta reutilizável. As exibições são úteis quando você precisa aplicar regras de negócios, simplificar junções complexas ou fornecer dados coletados para consumidores downstream. Por exemplo, você pode criar uma visão que une as tabelas de vendas e produtos e aplica filtros para somente exibir produtos ativos, facilitando o consumo dos dados por autores de relatório.

O ponto de extremidade de análise do SQL também dá suporte à **segurança em nível de linha** e à **segurança em nível de coluna**. Assim, você pode controlar os usuários que acessam os dados ao consultar usando o SQL.

> [!Dica]
> 
> 
> Copilot para consultas SQL pode ajudá-lo a escrever consultas T-SQL com descrições de linguagem natural. Você pode descrever o que deseja analisar e Copilot sugere código de consulta para atingir sua meta. Essa abordagem acelera a criação de consultas e ajuda você a aprender padrões T-SQL.

## Consultar dados com notebooks Spark

Os notebooks fornecem um ambiente flexível baseado em código para consultar e analisar dados do Lakehouse. Você pode usar o Spark SQL para consultas semelhantes a SQL ou PySpark para manipulação de dados programática. Os notebooks são valiosos quando você precisa executar a análise de dados exploratória, aplicar métodos estatísticos ou preparar dados para modelos de machine learning.

**Spark SQL vs PySpark:**

- **Spark SQL**: Use a sintaxe SQL em uma célula de notebook para consultar tabelas Lakehouse. Escreva consultas como `SELECT * FROM schema.table` para recuperar e analisar dados.
- **PySpark**: usar código Python para manipular dados. Você pode escrever consultas SQL usando `spark.sql()` ou usar a API DataFrame com métodos Python como `df.select()` e `df.filter()`.

Escolha a abordagem que se ajusta à sua preferência e à complexidade da sua análise. O SQL do Spark funciona bem para padrões SQL familiares. O PySpark oferece maior flexibilidade para transformações complexas e integração com bibliotecas de Python.

Casos de uso comuns para notebooks Spark incluem:

- **Análise de dados exploratória**: investigar padrões, exceções e relações nos dados.
- **Transformações complexas**: aplique uma lógica de negócios mais fácil de expressar em código do que o SQL.
- **Consultas entre workspaces**: use o namespace de quatro partes (`workspace.lakehouse.schema.table`) para unir dados em múltiplos lakehouses em uma única consulta.

> [!Dica]
> 
> 
> Copilot para notebooks pode produzir código PySpark ou Spark SQL com base em comandos de linguagem natural e explicar o código existente. Essa assistência de IA acelera o desenvolvimento e ajuda você a aprender a sintaxe do Spark enquanto trabalha.

## Analisar e visualizar com Power BI

Power BI é a camada de inteligência de negócios e relatórios no Fabric. Ele serve como a camada de consumo em que os usuários empresariais acessam dados por meio de relatórios e dashboards interativos.

Power BI pode se conectar aos dados do lakehouse de duas maneiras:

- **Consultar o endpoint de análise do SQL**: Os analistas podem se conectar diretamente ao endpoint de análise do SQL usando o Power BI ou outras ferramentas como o Excel para executar consultas "ad hoc" e explorar dados antes de criar relatórios.
- **Crie um modelo semântico**: você pode criar um modelo semântico que faça referência a tabelas específicas do lakehouse. Esse modelo define relações, medidas e lógica de negócios que os relatórios do Power BI consomem.

Quando você cria relatórios em um modelo semântico lakehouse, Power BI usa o modo **Direct Lake** por padrão. O Direct Lake lê dados diretamente dos arquivos delta lake parquet sem importar ou copiar dados. Essa abordagem fornece um desempenho de consulta rápido, garantindo que os relatórios sempre reflitam os dados atuais do Lakehouse.

Modelos semânticos também dão suporte a experiências inteligentes downstream. Quando você define relações claras e métricas de negócios em um modelo semântico, o Copilot no Power BI pode gerar visualizações e responder a questões de negócios, raciocinando sobre seus dados do lakehouse.
