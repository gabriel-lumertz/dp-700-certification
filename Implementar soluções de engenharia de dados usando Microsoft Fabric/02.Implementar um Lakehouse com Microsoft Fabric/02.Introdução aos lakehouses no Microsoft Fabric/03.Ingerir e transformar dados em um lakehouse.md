Seu lakehouse precisa de dados para poder fornecer insights. Se você estiver carregando arquivos do armazenamento local, conectando-se a dados entre nuvens ou criando pipelines de transformação, entender técnicas de ingestão e transformação é essencial. Comece criando um lakehouse e explorando as ferramentas disponíveis para deixar seus dados disponíveis e prontos para análise.

## Criar e explorar um lakehouse

Você cria lakehouses em um workspace habilitado para Fabric. Um lakehouse tem duas áreas de armazenamento principais e um endpoint de análise SQL.

- **Tabelas**: armazena tabelas Delta Lake que fornecem dados estruturados e que podem ser consultados. Essas tabelas dão suporte a consultas SQL, impõem esquemas e fornecem garantias de transação ACID. Você pode consultá-los por meio do endpoint de análise do SQL e analisá-los com o Power BI.
- **Arquivos**: armazena arquivos de dados brutos ou semiestruturados em seu formato nativo (CSV, JSON, Parquet e outros). Esses arquivos não impõem um esquema e fornecem flexibilidade para exploração e processamento de dados antes da transformação em tabelas.

Quando você cria um lakehouse, **os esquemas são habilitados por padrão**. Um esquema chamado **dbo** é criado automaticamente. Os esquemas permitem organizar tabelas em grupos lógicos com base em domínios ou funções de negócios, como `sales`, `marketing`ou `hr`. Você pode criar outros esquemas para manter as tabelas organizadas conforme o lakehouse cresce. Os lakehouses habilitados para esquema também dão suporte a permissões de nível de esquema e consultas entre espaços de trabalho usando o namespace de quatro partes (`workspace.lakehouse.schema.table`).

> [!Dica]
> 
> 
> A organização do esquema claro melhora a descoberta para todos que trabalham com o lakehouse, incluindo agentes de dados do Fabric IQ que convertem perguntas em linguagem natural em consultas SQL nas suas tabelas.

Você pode trabalhar com seu lakehouse de duas formas:

- **Gerenciador do Lakehouse**: adicione e interaja com tabelas, arquivos e pastas. Esse modo permite que você gerencie dados, carregue arquivos, crie tabelas e faça alterações no lakehouse. Você também pode adicionar lakehouses de referência ao painel do explorador, permitindo navegar e gerenciar tabelas em vários lakehouses simultaneamente.
- **Endpoint de análise SQL**: Executar consultas em tabelas Delta usando T-SQL no modo _somente leitura_. Você pode criar exibições, funções e aplicar a segurança do SQL, mas não pode modificar os dados subjacentes.

## Ingerir dados em um lakehouse

A ingestão de dados em seu lakehouse é a primeira etapa no processo de ETL (extrair, transformar, carregar). Use qualquer um dos métodos a seguir para inserir dados no lakehouse.

- **Upload**: carregar arquivos ou pastas locais diretamente pelo Lakehouse Explorer.
- **Carregar na Tabela**: selecione um arquivo ou pasta no Lakehouse Explorer e escolha **Carregar na Tabela** para criar uma tabela Delta sem escrever código. Essa opção sem código dá suporte a arquivos Parquet e CSV e permite acrescentar ou substituir dados em tabelas novas ou existentes.
- **Dataflows Gen2**: importar e transformar dados usando Power Query.
- **Notebooks**: Use o Apache Spark para ingerir, transformar e carregar dados programaticamente.
- **Pipelines do Data Factory**: Use a atividade de Copiar dados para mover dados de fontes externas.

Considere o padrão de carregamento de dados ao realizar a ingestão de dados. Você pode carregar dados brutos como arquivos para preparo e processamento posterior ou carregar diretamente em tabelas quando os dados já estiverem em um formato com suporte.

> [!Observação]
> 
> 
> Para obter mais informações sobre opções de ingestão, consulte as [Opções para obter dados na documentação do Fabric Lakehouse](https://learn.microsoft.com/pt-br/fabric/data-engineering/load-data-lakehouse) .

## Acessar dados utilizando atalhos

Os atalhos permitem integrar dados ao lakehouse sem a necessidade de copiá-los. Um atalho faz referência a dados no armazenamento externo e faz com que eles apareçam como uma pasta em seu lakehouse.

Os atalhos são valiosos porque reduzem a quantidade de vezes que você precisa copiar dados. Você pode criar um atalho para uma conta de armazenamento diferente, outro provedor de nuvem ou outros itens no Fabric. O OneLake gerencia as permissões e credenciais de dados de origem. Quando você acessa dados por meio de um atalho para outro local do OneLake, o OneLake usa sua identidade para autorizar o acesso aos dados de destino. Você deve ter permissões no local de destino para ler os dados.

Você também pode criar **atalhos schema** que mapeiam um esquema inteiro para uma pasta de tabelas Delta em outro lakehouse ou em Azure Data Lake Storage Gen2. Todas as tabelas referenciadas aparecem como tabelas locais dentro do esquema.

> [!Observação]
> 
> 
> Para obter mais informações sobre como usar atalhos, consulte a [documentação de atalhos do OneLake](https://learn.microsoft.com/pt-br/fabric/onelake/onelake-shortcuts).

## Transformar dados em um data lakehouse

A maioria dos dados requer transformação antes de carregar em tabelas. Você pode ingerir dados brutos diretamente na área Arquivos e, em seguida, transformá-los e carregá-los em tabelas. Independentemente do design de ETL, você pode transformar e carregar dados usando as mesmas ferramentas disponíveis para ingestão.

- **Os notebooks são favorecidos** por engenheiros de dados familiarizados com linguagens de programação, incluindo PySpark, SQL e Scala. Copilot em notebooks pode gerar código de transformação a partir de descrições de linguagem natural e explicar o código Spark existente.
- **Dataflows Gen2** são adequados para usuários familiarizados com Power BI ou Excel, pois usam a interface Power Query.
- **Os pipelines** fornecem uma interface visual para orquestrar processos ETL. Os pipelines podem incluir várias atividades que são executadas em sequência ou paralelo.
