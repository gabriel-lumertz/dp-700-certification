As arquiteturas de análise tradicionais geralmente forçam você a escolher entre duas abordagens. Os data lakes oferecem flexibilidade e escalabilidade, mas não têm a estrutura e o desempenho necessários para a análise de negócios. Os data warehouses fornecem recursos analíticos fortes, mas lutam com formatos de dados diversos e podem ser caros para dimensionar. Os **Lakehouses** preenchem essa lacuna, trazendo capacidades semelhantes a bancos de dados diretamente para o data lake, eliminando a necessidade de manter sistemas separados para diferentes cargas de trabalho.

## Entender o design do lakehouse

Uma lakehouse organiza dados em duas áreas principais: **Tabelas** e **Arquivos**. Entender essa separação ajuda você a criar fluxos de trabalho de dados eficazes.

**Pasta Tabelas**: essa pasta contém tabelas delta lake que fornecem dados estruturados e que podem ser consultados. Tabelas nesta pasta:

- Suporte a consultas SQL por meio do endpoint de análise SQL
- Impor esquemas e dar suporte a transações ACID
- Pode ser acessado em Power BI para relatórios
- Beneficiar-se da otimização e da manutenção automáticas

**Pasta arquivos**: essa pasta armazena arquivos de dados brutos ou semiestruturados em seu formato nativo. Arquivos nesta pasta:

- Suporta qualquer formato de arquivo (CSV, JSON, Parquet, imagens e documentos)
- Fornecer flexibilidade para exploração e processamento de dados
- Pode ser encenado antes da transformação em tabelas
- Não impor esquema nem dar suporte a consultas SQL diretas

Essa separação permite manter dados brutos (para conformidade ou reprocessamento) e tabelas estruturadas (para análise) dentro do mesmo lakehouse. Você pode processar arquivos usando notebooks Spark ou Fluxos de Dados Gen2 e, em seguida, carregar os resultados em tabelas para consulta e relatório.

## Entender as tabelas do Delta Lake

No centro de um lakehouse estão as **tabelas do Delta Lake**. O Delta Lake é uma camada de armazenamento de software livre que traz confiabilidade para data lakes. Quando você cria uma tabela em um lakehouse, os dados são armazenados no formato Delta no armazenamento subjacente do OneLake.

As tabelas delta lake fornecem várias vantagens principais:

- **Transações ACID**: o Delta Lake garante a consistência de dados mesmo quando vários usuários leem e gravam dados simultaneamente.
- **Imposição de esquema**: o Delta Lake valida que os dados gravados correspondem ao esquema de tabela, impedindo dados corrompidos.
- **Viagem no tempo**: o Delta Lake mantém um log de transações que permite consultar versões anteriores de seus dados ou reverter alterações.
- **Atualizações e exclusões eficientes**: ao contrário dos arquivos data lake tradicionais, as tabelas Delta dão suporte a operações eficientes de atualização e exclusão.

Cada tabela Delta consiste em arquivos de dados Parquet mais um log de transações que rastreia todas as alterações. Essa arquitetura permite que cargas de trabalho em lotes e streaming funcionem de forma confiável com os mesmos dados.

## Gerenciar o acesso ao Lakehouse

Quando você centraliza dados em seu lakehouse, proteger esses dados torna-se crítico. Fabric fornece controles de acesso em camadas para proteger os dados do lakehouse em vários níveis.

Use **funções de espaço de trabalho** para colaboradores que precisam de acesso a todos os itens no espaço de trabalho. Use **compartilhamento no nível de item** para conceder acesso somente leitura a necessidades específicas, como análise ou desenvolvimento de relatórios Power BI.

Para controle granular, o ponto de extremidade de análise do SQL dá suporte à segurança **no nível de linha** e **no nível da coluna**, para que você possa restringir o que os usuários específicos veem ao consultar por meio do SQL. Se você organizar tabelas em esquemas, também poderá aplicar **permissões no nível do esquema** para controlar o acesso por domínio empresarial.

Os Fabric Lakehouses também dão suporte a recursos de governança de dados, incluindo rótulos de confidencialidade, e podem ser estendidos usando o Microsoft Purview com sua instância do Fabric.

## Criar uma base para análise inteligente

Os dados que você estrutura em um lakehouse não servem apenas a relatórios e dashboards tradicionais. Dados bem organizados do lakehouse tornam-se uma base fundamental da qual as experiências inteligentes no Microsoft Fabric dependem.

Ao criar tabelas com esquemas claros, convenções de nomenclatura consistentes e nomes de coluna descritivos, você torna esses dados acessíveis para analistas humanos e ferramentas de IA. Os agentes de dados do Fabric IQ podem consultar suas tabelas lakehouse através do endpoint de análise SQL, traduzindo perguntas em linguagem natural em consultas SQL que retornam respostas precisas. A qualidade dessas respostas depende diretamente de quão bem você estrutura e documenta seus dados.

Os recursos do Copilot na plataforma Fabric também se beneficiam de dados bem estruturados do lakehouse. Copilot no Power BI pode gerar relatórios e responder a perguntas de negócios quando pode raciocinar sobre tabelas e relações claramente definidas. Os mesmos dados do lakehouse podem alimentar modelos semânticos que dão suporte à exploração de linguagem natural em experiências Microsoft 365.

Isso significa que o investimento feito na organização, nomenclatura e estruturação de dados do Lakehouse paga dividendos além de suas necessidades de análise imediata. Boas práticas de engenharia de dados na lakehouse criam uma base reutilizável para experiências inteligentes em toda a plataforma.
