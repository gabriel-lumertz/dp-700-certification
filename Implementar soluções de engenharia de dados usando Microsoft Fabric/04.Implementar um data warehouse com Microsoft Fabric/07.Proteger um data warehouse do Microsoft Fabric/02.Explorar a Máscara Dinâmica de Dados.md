O [DDM (Máscara Dinâmica de Dados)](https://learn.microsoft.com/pt-br/fabric/data-warehouse/dynamic-data-masking) é um recurso de segurança que limita a exposição de dados a usuários não privilegiados, ocultando informações confidenciais.

A Máscara Dinâmica de Dados oferece vários benefícios importantes que aprimoram a segurança e a capacidade de gerenciamento dos seus dados. Uma das principais vantagens é o recurso de mascaramento em tempo real. Ao consultar dados confidenciais, o DDM aplica a máscara dinâmica a ele em tempo real. Esse processo significa que os dados reais nunca são expostos a usuários não autorizados, aprimorando a segurança dos seus dados. Além disso, o DDM é simples de implementar. Ele não exige codificação complexa, tornando-o acessível para usuários de todos os níveis de habilidade.

Outro benefício do DDM é que os dados do banco de dados não são alterados quando o DDM é aplicado. Em vez disso, as regras de mascaramento são aplicadas aos resultados da consulta. Esse benefício significa que os dados reais permanecem intactos e seguros, enquanto os usuários não privilegiados veem apenas uma versão mascarada dos dados.

## Definir a regra de mascaramento

A Máscara Dinâmica de Dados, que é configurada na coluna, oferece um conjunto de recursos, incluindo funcionalidades abrangentes e parciais de mascaramento, juntamente com uma função de mascaramento aleatória projetada para dados numéricos.

|Tipo de mascaramento|Descrição|Caso de uso|Limitações|Regra de mascaramento|
|---|---|---|---|---|
|**Padrão**|Mascaramento completo de acordo com os tipos de dados dos campos designados.|Útil quando você deseja ocultar completamente os dados reais.|Mascara completamente os dados. Nenhuma informação fica visível.|`default()`|
|**Email**|Expõe a primeira letra de um endereço de email e o sufixo constante “.com”|Útil quando você deseja mostrar que o campo de dados contém um email sem revelar o email real.|Aplicável somente aos campos de email.|`email()`|
|**Texto personalizado**|Expõe os primeiros e últimos ‘n’ caracteres e adiciona uma cadeia de caracteres de preenchimento personalizada no meio.|Útil quando você deseja ocultar parcialmente os dados reais.|Não adequado para tipos de dados numéricos, data e hora.|`partial(prefix_padding, padding_string, suffix_padding)`|
|**Aleatório**|Substitui qualquer valor numérico ou binário por um número aleatório dentro de um intervalo especificado.|Útil quando você deseja ocultar os dados numéricos ou binários reais.|Aplicável somente a tipos de dados numéricos e binários.|`random(low, high)`|

Os parâmetros `prefix_padding` e `suffix_padding` na função `partial()` especificam o número de caracteres a serem expostos no início e no final da cadeia de caracteres, enquanto o parâmetro `padding_string` especifica a cadeia de caracteres a ser usada para mascarar os caracteres restantes.

Os parâmetros `low` e `high` na função `random()` especificam o intervalo de números aleatórios a serem gerados.

Esses tipos de mascaramento ajudam a impedir a exibição não autorizada de dados confidenciais, permitindo que os administradores especifiquem o volume de dados confidenciais a serem revelados, com efeito mínimo na camada do aplicativo. Eles são aplicados aos resultados da consulta, portanto, os dados no banco de dados não são alterados. Essa abordagem permite que muitos aplicativos mascarem dados confidenciais sem modificar as consultas existentes.

### Configurar o mascaramento de dados

Vamos considerar um exemplo de um warehouse que armazena informações do cliente. O warehouse contém uma tabela `Customer` com campos como `CustomerName`, `Email`, `PhoneNumber` e `CreditCardNumber`.

Para aplicar o mascaramento de dados nas colunas `CustomerName`, `Email`, `PhoneNumber` e `CreditCardNumber`, execute o seguinte comando:

Transact-SQL

```
-- For Email
ALTER TABLE Customers
ALTER COLUMN Email ADD MASKED WITH (FUNCTION = 'email()');

-- For PhoneNumber
ALTER TABLE Customers
ALTER COLUMN PhoneNumber ADD MASKED WITH (FUNCTION = 'partial(0,"XXX-XXX-",4)');

-- For CreditCardNumber
ALTER TABLE Customers
ALTER COLUMN CreditCardNumber ADD MASKED WITH (FUNCTION = 'partial(0,"XXXX-XXXX-XXXX-",4)');
```

## Exibir os resultados mascarados

Sem a Máscara Dinâmica de Dados, se um usuário não privilegiado executar uma consulta para buscar detalhes do cliente, ele poderá ver algo assim:

```
CustomerName: John Doe
Email: johndoe@contoso.com
PhoneNumber: 123-456-7890
CreditCardNumber: 1234-5678-9012-3456
```

No entanto, com o DDM aplicado aos campos `Email`, `PhoneNumber` e `CreditCardNumber`, a mesma consulta retornará:

```
CustomerName: John Doe
Email: j*****@contoso.com
PhoneNumber: XXX-XXX-7890
CreditCardNumber: XXXX-XXXX-XXXX-3456
```

Como você pode ver, os dados confidenciais ficam ocultos do usuário não privilegiado, aumentando a segurança dos dados. Esse cenário é um exemplo básico de como funciona a Máscara Dinâmica de Dados. Ela ajuda a garantir que dados confidenciais não sejam expostos a usuários que não tenham os privilégios necessários para exibi-los.

> [!Observação]
> 
> 
> Os usuários sem privilégios com permissões de consulta podem inferir os dados reais, pois os dados não são ocultados fisicamente.

O DDM deve ser usado como parte de uma estratégia de segurança de dados abrangente que inclui o gerenciamento adequado da segurança em nível de objeto com permissões granulares do SQL e adesão ao princípio de permissões mínimas necessárias.
