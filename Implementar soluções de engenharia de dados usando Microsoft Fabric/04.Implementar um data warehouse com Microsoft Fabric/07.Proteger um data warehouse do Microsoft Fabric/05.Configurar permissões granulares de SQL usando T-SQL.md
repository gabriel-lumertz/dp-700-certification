Se você estiver familiarizado com bancos de dados relacionais e armazéns empresariais, é de conhecimento geral que há quatro permissões fundamentais que regem as operações [de DML (Linguagem de Manipulação de Dados](https://learn.microsoft.com/pt-br/sql/t-sql/queries/queries) ). Essas permissões, a saber, `SELECT`, `INSERT`, `UPDATE` e `DELETE`, são universalmente aplicáveis em todas as plataformas de banco de dados.

Todas essas permissões podem ser concedidas, revogadas ou negadas nas tabelas e exibições. Se uma permissão for concedida usando a instrução `GRANT`, ela será dada ao usuário ou função referenciada na instrução `GRANT`. As permissões também podem ser negadas aos usuários usando o comando `DENY`. Se um usuário receber uma permissão e a mesma permissão for negada a ele, `DENY` sempre substituirá a concessão, e o acesso do usuário ao objeto específico será negado.

## Permissões de tabela e exibição

As tabelas e as exibições representam os objetos em que as permissões podem ser concedidas em um warehouse. Nessas tabelas e exibições, você pode restringir ainda mais as colunas acessíveis a uma entidade de segurança específica.

|Permissão|Definição|
|---|---|
|`SELECT`|Permite ao usuário exibir os dados dentro do objeto (tabela ou exibição). Quando negada, o usuário é impedido de exibir os dados no objeto.|
|`INSERT`|Permite ao usuário inserir dados no objeto. Quando negada, o usuário é impedido de inserir os dados no objeto.|
|`UPDATE`|Permite ao usuário atualizar dados dentro do objeto. Quando negada, o usuário é impedido de inserir os dados no objeto.|
|`DELETE`|Permite ao usuário excluir dados dentro do objeto. Quando negada, o usuário é impedido de excluir os dados do objeto.|

## Permissões de função e procedimento armazenado

Assim como as tabelas e as exibições, as funções e os procedimentos armazenados têm várias permissões que podem ser concedidas ou negadas.

|Permissão|Definição|
|---|---|
|`ALTER`|Concede ao usuário a capacidade de alterar a definição do objeto.|
|`CONTROL`|Concede ao usuário todos os direitos ao objeto.|

## Princípio de privilégios mínimos

A ideia básica do princípio de privilégios mínimos consiste no fato de que os usuários e os aplicativos só devem receber as permissões necessárias para concluir a tarefa. Os aplicativos devem ter apenas as permissões necessárias para concluir a tarefa em questão.

Por exemplo, se um aplicativo acessa todos os dados por meio de procedimentos armazenados, o aplicativo deve ter apenas a permissão para executar os procedimentos armazenados, sem acesso às tabelas.

### SQL dinâmico

O SQL dinâmico é um conceito em que uma consulta é criada programaticamente. O SQL dinâmico permite que instruções T-SQL sejam geradas em um procedimento armazenado ou na própria consulta. Um exemplo simples é mostrado abaixo.

SQL

```
CREATE PROCEDURE sp_TopTenRows @tableName NVARCHAR(128)
AS
BEGIN
    DECLARE @query NVARCHAR(MAX);
    SET @query = N'SELECT TOP 10 * FROM ' + QUOTENAME(@tableName);
    EXEC sp_executesql @query;
END;
```

Neste exemplo, `@tableName` é o parâmetro que você pode substituir pelo nome da tabela que deseja inspecionar. A função `QUOTENAME` é usada para citar com segurança o nome da tabela, impedindo ataques de injeção de SQL. Em seguida, o procedimento armazenado `sp_executesql` é usado para executar a consulta criada dinamicamente.

Observe que esse é um exemplo simples e as tarefas do data warehouse do mundo real podem exigir consultas SQL dinâmicas mais complexas. Sempre tenha cuidado ao usar o SQL dinâmico, devido ao risco de ataques de injeção de SQL. Sempre use métodos de parametrização como `sp_executesql` ou `QUOTENAME` para limpar as entradas.
