Os desenvolvedores SQL ou os desenvolvedores cidadãos, que geralmente são bem versados no mecanismo SQL e hábeis no uso do T-SQL, encontrarão o Warehouse no Microsoft Fabric favorável.

Isso ocorre porque o Warehouse é alimentado pelo mesmo mecanismo SQL com o qual eles estão familiarizados, permitindo que eles realizem consultas complexas e manipulações de dados. Essas operações incluem filtragem, classificação, agregação e junção de dados de diferentes tabelas. O amplo intervalo de funções e operadores do mecanismo SQL análises de dados sofisticadas e transformações no nível do banco de dados.

## Usar a instrução COPY

A [instrução COPY](https://learn.microsoft.com/pt-br/sql/t-sql/statements/copy-into-transact-sql) serve como o principal método para importar dados no Warehouse. Ele facilita a ingestão de dados eficiente de uma conta externa de armazenamento do Microsoft Azure.

Ele oferece flexibilidade, permitindo que você especifique o formato do arquivo de origem, designe um local para armazenar as linhas rejeitadas durante o processo de importação, ignore as linhas de cabeçalho, entre outras opções configuráveis.

A opção para armazenar separadamente as linhas rejeitadas é útil para a limpeza de dados e o controle de qualidade. Isso lhe permite identificar e investigar facilmente quaisquer problemas com os dados que não foram importados com êxito.

Para conectar você a uma conta de armazenamento do Azure, é necessário usar a Assinatura de Acesso Compartilhado (SAS) ou a Chave da Conta de Armazenamento (SAK).

### Tratar os erros

A opção de usar uma conta de armazenamento diferente para o local _ERRORFILE_ (`REJECTED_ROW_LOCATION`) permite um melhor tratamento de erros e depuração. Isso facilita o isolamento e a investigação de quaisquer problemas que ocorram durante o processo de carregamento de dados. _ERRORFILE_ aplica-se somente ao CSV.

### Carregar vários arquivos

A capacidade de especificar curingas e vários arquivos no caminho do local de armazenamento permite que a instrução COPY lide com o carregamento eficiente de dados em massa. Isso é útil ao lidar com grandes conjuntos de dados distribuídos em vários arquivos.

Vários locais de arquivos só podem ser especificados a partir da mesma conta de armazenamento e contêiner por meio de uma lista separada por vírgulas.

SQL

```
COPY INTO my_table
FROM 'https://myaccount.blob.core.windows.net/myblobcontainer/folder0/*.csv, 
    https://myaccount.blob.core.windows.net/myblobcontainer/folder1/'
WITH (
    FILE_TYPE = 'CSV',
    CREDENTIAL=(IDENTITY= 'Shared Access Signature', SECRET='<Your_SAS_Token>')
    FIELDTERMINATOR = '|'
)
```

O exemplo a seguir mostra como carregar um arquivo PARQUET.

SQL

```
COPY INTO test_parquet
FROM 'https://myaccount.blob.core.windows.net/myblobcontainer/folder1/*.parquet'
WITH (
    CREDENTIAL=(IDENTITY= 'Shared Access Signature', SECRET='<Your_SAS_Token>')
)
```

Certifique-se de que todos os arquivos tenham a mesma estrutura (ou seja, as mesmas colunas na mesma ordem) e que essa estrutura corresponda à estrutura da tabela de destino.

## Carregar a tabela de outros warehouses e lakehouses.

É possível carregar dados de vários ativos de dados em um espaço de trabalho, como outros warehouses e lakehouses.

Para referenciar o ativo de dados, certifique-se de usar a [nomenclatura de três partes](https://learn.microsoft.com/pt-br/sql/t-sql/language-elements/transact-sql-syntax-conventions-transact-sql) para combinar dados de tabelas nesses ativos de espaço de trabalho. Em seguida, você pode usar `CREATE TABLE AS SELECT` (CTAS) e `INSERT...SELECT` para carregar os dados no data warehouse.

|Instrução SQL|Descrição|
|---|---|
|[**`CREATE TABLE AS SELECT`**](https://learn.microsoft.com/pt-br/sql/t-sql/statements/create-table-as-select-azure-sql-data-warehouse)|Permite criar uma nova tabela com base na saída de uma instrução `SELECT`. Essa operação é frequentemente usada para a criação de uma cópia de uma tabela ou para transformar e carregar os resultados de consultas complexas.|
|[**`INSERT...SELECT`**](https://learn.microsoft.com/pt-br/sql/t-sql/statements/insert-transact-sql)|Permite inserir os dados de uma tabela em outra. É útil quando você deseja copiar os dados de uma tabela para outra sem criar uma nova tabela.|

Em um cenário em que um analista precisa de dados de um warehouse e de um Lakehouse, ele pode usar esse recurso para combinar os dados. Em seguida, eles podem carregar esses dados combinados no data warehouse para análise. Esse recurso é útil quando os dados são distribuídos em muitos ativos em um espaço de trabalho.

A consulta a seguir cria uma nova tabela em `analysis_warehouse` que combina dados de `sales_warehouse` e `social_lakehouse` usando _product_id_ como chave comum. A nova tabela pode então ser usada para análises adicionais.

SQL

```
CREATE TABLE [analysis_warehouse].[dbo].[combined_data]
AS
SELECT *
FROM [sales_warehouse].[dbo].[sales_data] sales
INNER JOIN [social_lakehouse].[dbo].[social_data] social
ON sales.[product_id] = social.[product_id];
```

Todos os Warehouses que compartilham o mesmo espaço de trabalho são integrados ao mesmo SQL Server lógico. Se você usar ferramentas de cliente SQL, como o [SQL Server Management Studio](https://learn.microsoft.com/pt-br/sql/ssms/download-sql-server-management-studio-ssms), poderá facilmente realizar uma consulta entre bancos de dados, da mesma forma que faria em qualquer instância do SQL Server.

![GIF animado mostrando como fazer referência a outros Warehouses em um workspace do SQL Server Management Studio.](https://learn.microsoft.com/pt-br/training/wwl-data-ai/load-data-into-microsoft-fabric-data-warehouse/media/4-load-using-ssms.gif)

_MyWarehouse_ e _Sales_ são ativos de warehouse que compartilham o mesmo espaço de trabalho.

Se você estiver usando o Pesquisador de Objetos a partir do espaço de trabalho para consultar seus Warehouses, você precisará adicioná-los explicitamente. Os warehouses adicionados também serão visíveis no editor de consulta Visual.

![GIF animado mostrando como consultar outros Warehouses em um workspace do workspace do Fabric.](https://learn.microsoft.com/pt-br/training/wwl-data-ai/load-data-into-microsoft-fabric-data-warehouse/media/4-query-using-workspace.gif)

Os dados podem ser carregados de maneira eficiente em um warehouse no Microsoft Fabric por meio da instrução COPY, ou de outros warehouses e lakehouses dentro do mesmo workspace, permitindo um gerenciamento e análise de dados contínuos.
