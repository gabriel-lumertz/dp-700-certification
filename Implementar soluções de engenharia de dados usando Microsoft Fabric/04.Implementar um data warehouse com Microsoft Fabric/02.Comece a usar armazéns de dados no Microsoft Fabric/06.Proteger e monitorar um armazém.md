Segurança e monitoramento são aspectos críticos do gerenciamento do data warehouse. O Fabric fornece várias camadas de ferramentas de proteção e visibilidade para ajudá-lo a controlar o acesso e compreender o desempenho de consultas.

## Segurança

A segurança do armazenamento de dados do Fabric opera em vários níveis, desde o acesso ao espaço de trabalho até linhas e colunas individuais. Esse design permite que você dê suporte às necessidades distintas de sua organização, permitindo ainda a democratização dos dados, mas com governança.

### Funções do espaço de trabalho

Os dados no Fabric são organizados em _workspaces_ e as funções de workspace são a primeira camada de access control. Atribua usuários a funções apropriadas com base no nível de acesso de que eles precisam. Por exemplo, os administradores têm controle total, enquanto os visualizadores podem exibir itens, mas não podem fazer alterações.

> [!Dica]
> 
> 
> Para obter mais informações, consulte [Workspaces no Power BI](https://learn.microsoft.com/pt-br/power-bi/collaborate-share/service-new-workspaces#roles-and-licenses).

### Permissões de item

Além das funções de workspace, você pode conceder **permissões de item** para compartilhar warehouses individuais sem conceder acesso para todo o workspace. Essa granularidade é útil quando você precisa compartilhar um warehouse para consumo downstream com usuários específicos.

Conceda as seguintes permissões conforme necessário:

- **Ler** – Permite que o usuário se conecte usando o endpoint de análise do SQL.
- **ReadData** - Permite ao usuário ler dados de qualquer tabela ou visualização no warehouse.
- **ReadAll** – Permite que o usuário leia arquivos parquet brutos no OneLake.

> [!Observação]
> 
> 
> A conexão de um usuário ao endpoint de análises SQL falha sem, no mínimo, a permissão de leitura.

### Segurança do SQL granular

Para um controle de acesso mais preciso, o data warehouse Fabric oferece suporte à segurança granular com T-SQL. Esses recursos permitem restringir a visibilidade de dados sem alterar as tabelas subjacentes:

- **Object-level security** – Controle acesso a tabelas, visões ou procedimentos específicos.
- **RLS (segurança em nível de linha)** – restrinja quais linhas um usuário pode ver usando predicados de cláusula WHERE.
- **CLS (segurança em nível de coluna)** – restrinja quais colunas estão visíveis para usuários específicos.
- **Mascaramento dinâmico de dados – mascarar** dados confidenciais (como endereços de email ou números de conta) de usuários não privilegiados.

Proteger seus dados de warehouse é importante tanto para a conformidade regulatória quanto para garantir que ferramentas alimentadas por IA, como Copilot e agentes de dados, operem dentro dos limites controlados. As políticas de segurança definidas no T-SQL são impostas independentemente de como os dados são acessados.

> [!Dica]
> 
> 
> A segurança em nível de linha, a segurança em nível de coluna e o mascaramento de dados dinâmicos são abordados detalhadamente em [Secure um Microsoft Fabric data warehouse](https://learn.microsoft.com/pt-br/training/modules/secure-data-warehouse-in-microsoft-fabric/).

## Monitorização

Monitorar a atividade do warehouse ajuda você a identificar problemas de desempenho, otimizar consultas e entender padrões de uso.

### Insights de consulta

_Query Insights_ fornece um local central para dados de consulta históricos e informações de desempenho acionáveis. Ele retém dados por 30 dias e ajuda a identificar consultas de longa execução, controlar alterações de desempenho ao longo do tempo e entender quais consultas consomem mais recursos.

Os insights de consulta usam visões do sistema que você pode consultar diretamente.

- `queryinsights.exec_requests_history` - Retorna informações sobre cada solicitação SQL concluída.
- `queryinsights.long_running_queries` - Retorna consultas classificadas por tempo de execução.
- `queryinsights.exec_sessions_history` - Retorna informações sobre sessões concluídas.

### Visões de gerenciamento dinâmico

Você também pode usar _exibições de gerenciamento dinâmico_ (DMVs) para monitorar conexões ativas, sessões e solicitações em tempo real. Por exemplo, use `sys.dm_exec_requests` para identificar as consultas em execução no momento:

SQL

```
SELECT request_id, session_id, start_time, total_elapsed_time
FROM sys.dm_exec_requests
WHERE status = 'running'
ORDER BY total_elapsed_time DESC;
```

> [!Importante]
> 
> 
> Você deve ser um Administrador do workspace para executar o `KILL` comando para encerrar sessões de longa execução. Membros, Colaboradores e Visualizadores podem ver seus próprios resultados, mas não podem ver as consultas de outros usuários.
