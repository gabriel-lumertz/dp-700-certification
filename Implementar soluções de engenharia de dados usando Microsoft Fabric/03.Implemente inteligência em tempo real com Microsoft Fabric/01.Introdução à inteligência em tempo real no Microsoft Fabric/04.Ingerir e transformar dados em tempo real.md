A Inteligência em Tempo Real no Microsoft Fabric fornece duas abordagens principais para ingerir dados de streaming: usar Eventstreams ou ingerir dados diretamente em um banco de dados KQL em um Eventhouse.

## Eventstreams para ingestão e transformação de dados

Os Eventstreams são uma maneira de trazer eventos em tempo real para o Fabric, transformá-los e, em seguida, rotear dados para um destino.

[![Captura de tela de um Eventstream no Microsoft Fabric.](https://learn.microsoft.com/pt-br/training/wwl/get-started-kusto-fabric/media/eventstream.png)](https://learn.microsoft.com/pt-br/training/wwl/get-started-kusto-fabric/media/eventstream.png#lightbox)

A imagem mostra os três principais componentes de um Eventstream: **fontes**, de onde os dados se originam; **transformações**, processamento opcional aplicado aos dados; e **destinos**, para onde os dados processados são enviados.

Pense nos componentes do Eventstream como um sistema de tubulação de água. A origem é sua torneira, as transformações são filtros ao longo do caminho e você precisa de um destino, como uma pia ou um balde, para coletar e usar a água.

Em seguida, vamos examinar cada componente de um Eventstream.

## Fontes de dados para fluxos de eventos

Depois de criar um fluxo de eventos no Fabric, você poderá conectá-lo a uma ampla gama de fontes de dados. Você pode transmitir dados de fontes da Microsoft e também ingerir dados de plataformas que não são da Microsoft, incluindo:

- **Fontes da Microsoft**, como Hubs de Eventos do Azure, Hubs IoT do Azure, Barramento de Serviço do Azure, feeds da CDC (Captura de dados de alterações) em serviços de banco de dados e outros.
- **Eventos do Azure**, como eventos do Armazenamento de Blobs do Azure.
- **Eventos do Fabric**, como alterações em itens em um workspace do Fabric, alterações de dados em armazenamentos de dados do OneLake e eventos relacionados a trabalhos no Fabric.
- **Fontes externas**, como Apache Kafka, Google Cloud Pub/Sub e MQTT (Message Queuing Telemetry Transport) (em versão prévia)

>

## Transformações de eventos em fluxos de eventos

Os dados brutos de um sistema de origem raramente estão exatamente no formato necessário para análise ou armazenamento. As transformações são o que tornam seus dados úteis e acionáveis. Você pode transformar os dados conforme eles fluem em um fluxo de eventos, permitindo filtrar, resumir e remodelá-los antes de armazená-los. Os exemplos de transformações disponíveis incluem: código SQL, filtro, gerenciar campos, agregar, agrupar por, expandir e ingressar.

> [!Dica]
> 
> 
> Para obter mais informações sobre as transformações com suporte, veja **[Processar dados de eventos com o editor do processador de eventos](https://learn.microsoft.com/pt-br/fabric/real-time-intelligence/event-streams/process-events-using-event-processor-editor)** e **[Processar eventos usando o editor de código SQL](https://learn.microsoft.com/pt-br/fabric/real-time-intelligence/event-streams/process-events-using-sql-code-editor)**.

## Destinos de dados em fluxos de eventos

O streaming de dados flui continuamente e é temporário por natureza. Ele requer processamento e armazenamento imediatos para manter seu valor. O destino em um fluxo de eventos é o que torna o processamento de dados em tempo real acionável. É onde seus dados processados ficam disponíveis para consultas, relatórios, dashboards, alertas, ações ou integração com outros sistemas. Você pode carregar os dados do seu fluxo para os seguintes destinos: um banco de dados KQL em um Eventhouse, Lakehouse, um fluxo derivado, o Fabric Activator ou um ponto de extremidade personalizado.

## Ingestão direta para um banco de dados KQL em um Eventhouse

Os dados também podem ser ingeridos diretamente em um banco de dados KQL (Linguagem de Consulta Kusto) em um Eventhouse. Alguns exemplos de fontes de ingestão de dados incluem: arquivos locais, armazenamento do Azure, Amazon S3, Hubs de Eventos do Azure, OneLake e muito mais. A ingestão de dados pode ser configurada usando **conectores** ou por meio da opção **Obter dados** em um banco de dados KQL, conforme mostrado nesta imagem.

## Transformação de dados em um banco de dados KQL no Eventhouse com as políticas de atualização

Ao ingerir dados diretamente em um banco de dados KQL, primeiro, os dados chegam ao banco de dados e, em seguida, podem ser transformados usando as **políticas de atualização**. Isso é diferente das transformações de fluxo de eventos que ocorrem _durante_ o processamento de fluxo, antes de rotear dados para um destino.

As políticas de atualização são mecanismos de automação disparados quando novos dados são gravados em uma tabela. Elas executam uma consulta para transformar dados ingeridos e salvar o resultado em uma tabela de destino.
