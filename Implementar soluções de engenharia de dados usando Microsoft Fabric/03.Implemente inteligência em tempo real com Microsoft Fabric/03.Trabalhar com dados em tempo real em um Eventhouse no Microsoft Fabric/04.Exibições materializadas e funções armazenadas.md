Agora que você entende as técnicas básicas de consulta e otimização de KQL, vamos explorar exibições materializadas e funções armazenadas em casas de eventos.

## Entender exibições materializadas

Exibições materializadas são agregações pré-computadas que resolvem um desafio de desempenho comum em bancos de dados KQL. Os bancos de dados KQL em casas de eventos geralmente contêm milhões ou bilhões de linhas de fontes de dados de streaming, como sensores de IoT, logs de aplicativos e outros eventos. A execução de consultas de agregação entre esses grandes conjuntos de dados pode levar um tempo significativo e recursos de computação.

As exibições materializadas armazenam resultados de agregação pré-compilados e os atualizam automaticamente à medida que novos dados chegam. Em vez de recalcular métricas de todos os dados históricos toda vez que você consulta, a exibição materializada mantém os resultados e processa apenas os novos dados para atualizar as agregações. Isso fornece resultados instantâneos para dashboards e relatórios, mesmo ao trabalhar com conjuntos de dados maciços.

### Como funcionam as atualizações automáticas

Uma exibição materializada consiste em duas partes que trabalham juntas para fornecer resultados sempre atuais:

- **Uma parte materializada**: a agregação pré-computada resulta de dados que já foram processados
- **Um delta**: novos dados que chegaram desde a última atualização em segundo plano

Quando você consulta uma exibição materializada, o sistema combina automaticamente as duas partes no momento da consulta para fornecer resultados novos up-todata. Isso significa que as exibições materializadas sempre retornam dados atuais, independentemente de quando o processo de materialização em segundo plano foi executado pela última vez. Enquanto isso, um processo em segundo plano move periodicamente os dados da parte delta para a parte materializada, mantendo os resultados pré-compilados atuais. Essa abordagem fornece a velocidade dos resultados pré-compilados com a atualização dos dados em tempo real.

### Criar visualizações materializadas

Uma exibição materializada encapsula uma instrução **de resumo** KQL que é atualizada automaticamente à medida que novos dados chegam. Aqui está um exemplo que acompanha as métricas de viagem por fornecedor e dia:

kql

```
.create materialized-view TripsByVendor on table TaxiTrips
{
    TaxiTrips
    | summarize trips = count(), avg_fare = avg(fare_amount), total_revenue = sum(fare_amount)
    by vendor_id, pickup_date = format_datetime(pickup_datetime, "yyyy-MM-dd")
}
```

### Visualizações materializadas de consulta

Depois de criadas, as exibições materializadas podem ser consultadas como tabelas regulares:

kql

```
TripsByVendor
| where pickup_date >= ago(7d)
| project pickup_date, vendor_id, trips, avg_fare, total_revenue
| sort by pickup_date desc, total_revenue desc
```

## Entender as funções armazenadas

O KQL inclui a capacidade de encapsular uma consulta como uma função, facilitando a repetição de consultas comuns. Você também pode especificar parâmetros para uma função, para que você possa repetir a mesma consulta com valores variáveis.

As funções armazenadas são úteis em casas de eventos em que você tem dados de streaming e várias pessoas escrevendo consultas. Em vez de escrever a mesma lógica de filtragem ou transformação repetidamente, você pode defini-la uma vez como uma função e reutilizá-la em diferentes consultas. As funções também ajudam a garantir que os cálculos sejam executados consistentemente quando diferentes membros da equipe precisam aplicar a mesma lógica aos dados.

### Criar uma função

kql

```
.create-or-alter function trips_by_min_passenger_count(num_passengers:long)
{
    TaxiTrips
    | where passenger_count >= num_passengers 
    | project trip_id, pickup_datetime
}
```

Para chamar a função, use-a como uma tabela. Neste exemplo, a função **trips_by_min_passenger_count** é usada para localizar 10 viagens com pelo menos três passageiros:

kql

```
trips_by_min_passenger_count(3)
| take 10
```
