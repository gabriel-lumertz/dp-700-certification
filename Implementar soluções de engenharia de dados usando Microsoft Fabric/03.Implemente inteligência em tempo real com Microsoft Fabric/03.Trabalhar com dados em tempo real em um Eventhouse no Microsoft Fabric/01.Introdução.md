Um Eventhouse no Microsoft Fabric fornece um armazenamento de dados para grandes volumes de dados. É um contêiner que abriga um ou mais bancos de dados KQL, cada um otimizado para armazenar e analisar dados em tempo real que chegam continuamente de várias fontes.

Você pode carregar dados em um banco de dados KQL em um Eventhouse usando um Eventstream ou ingerir dados diretamente em um banco de dados KQL. Depois de ingerir dados, você poderá:

- Consulte os dados usando KQL (Linguagem de Consulta Kusto) ou T-SQL em um conjunto de consultas KQL.
- Use Real-Time Dashboards para visualizar os dados.
- Use o Ativador do Fabric para automatizar ações com base nos dados.

Entender como os bancos de dados KQL funcionam ajuda você a escrever consultas eficazes para analisar dados em tempo real. Neste módulo, você aprenderá sobre as características que tornam os bancos de dados KQL ideais para dados em tempo real e, em seguida, aplicará esse conhecimento explorando técnicas de consulta KQL e objetos de banco de dados, como exibições materializadas e funções armazenadas.

## Como os bancos de dados KQL funcionam com dados em tempo real?

Bancos de dados KQL particionam dados automaticamente por tempo de ingestão, tornando os dados recentes rapidamente acessíveis ao armazenar dados históricos para análise de tendências. _Particionamento_ significa que o banco de dados organiza dados em locais de armazenamento separados com base em quando ele chegou, portanto, quando você consulta dados recentes, o banco de dados sabe exatamente onde pesquisar em vez de verificar todos os dados.

Pense nisso como uma correia transportadora digital - os eventos fluem continuamente, são organizados automaticamente quando chegam e estão imediatamente disponíveis para análise enquanto o fluxo continua fluindo.

Essa organização baseada em tempo automático funciona porque os dados em tempo real têm uma característica exclusiva: ela representa eventos imutáveis que ocorreram em momentos específicos no tempo. _Imutável_ significa que esses eventos não podem ser alterados uma vez que ocorreram - uma leitura de temperatura às 15:15 sempre será essa leitura porque representa o que realmente aconteceu naquele momento. Como cada evento está permanentemente vinculado a quando aconteceu, isso cria o que chamamos **de dados de série temporal** - dados em que o carimbo de data/hora geralmente é tão importante quanto o evento em si.

Os dados de série temporal seguem um padrão somente acréscimo em que novos eventos são adicionados continuamente e os dados raramente são atualizados ou excluídos porque os eventos representam o que realmente aconteceu em momentos específicos. Isso é fundamentalmente diferente dos bancos de dados relacionais tradicionais, em que você normalmente atualiza registros existentes e mantém relações entre tabelas de dados diferentes.
