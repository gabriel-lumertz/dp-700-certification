Antes de avaliar as condições e disparar ações em dados em tempo real, você precisa configurar como o Activator deve interpretar seus dados para avaliação de regra. As regras avaliam as condições em relação a pontos de dados específicos , como "quando a temperatura deste pacote excede 86°F" ou "quando qualquer entrega leva mais de 48 horas".

Há várias maneiras de configurar o Activator para monitorar seus dados. Uma abordagem usa **objetos de negócios** – representando as coisas do mundo real que você deseja monitorar, como pacotes, dispositivos ou clientes.

## Entender objetos de negócios

Os objetos de negócios representam as entidades que você deseja monitorar. Para uma empresa de entrega de pacotes, cada pacote se torna um **objeto** no Activator. Cada objeto tem **propriedades** que são os pontos de dados específicos que você deseja monitorar.

Veja como esta organização funciona:

- **Objetos representam instâncias** individuais (Package001, Package002, Package003)
- **As propriedades** representam os atributos de dados para cada instância (Temperature, City, DeliveryState, HoursInTransit)
- **Os eventos** contêm os valores de dados reais que fluem de suas fontes de dados

Suas fontes de dados enviam eventos que contêm informações para vários pacotes. O Activator usa esses dados de entrada para atualizar automaticamente os valores de propriedade para cada objeto de pacote.

## Criar objetos a partir de fluxos de eventos

Ao configurar o Activator como um destino para um fluxo de eventos, você pode criar objetos de negócios no Activator. Durante essa configuração, você informa ao Activator quais campos de dados representam objetos e quais campos são propriedades a serem avaliadas.

Veja como você cria objetos a partir de um fluxo de eventos:

1. **Configurar o Ativador como um destino** – Em um fluxo de eventos
2. **Abrir o Ativador** – em seguida, selecione a opção para criar um novo objeto
3. **Escolha seu identificador exclusivo** - Selecione o campo que identifica exclusivamente o objeto (como PackageId ou DeviceID)
4. **Selecionar propriedades** – Escolha quais campos de dados você deseja monitorar como propriedades

Por exemplo, se o fluxo de eventos contiver dados de entrega de pacote com campos como `PackageId`, `Temperature`, `City`, `DeliveryState`e `HoursInTransit`, você pode:

- Use `PackageId` como seu identificador exclusivo para criar objetos de pacote separados
- Selecionar `Temperature` e `HoursInTransit` como propriedades que você deseja monitorar
- Deixar o Activator criar automaticamente objetos para cada pacote único conforme os dados fluem para dentro.

[![Captura de tela mostrando a interface do Ativador para criar um novo objeto](https://learn.microsoft.com/pt-br/training/wwl/use-fabric-activator/media/create-object.png)](https://learn.microsoft.com/pt-br/training/wwl/use-fabric-activator/media/create-object.png#lightbox)

Depois de configurado, o fluxo de eventos alimenta continuamente os dados para o Activator. Novos eventos atualizam as propriedades de objeto existentes, novos identificadores exclusivos criam automaticamente novos objetos e os valores de propriedade sempre refletem os dados mais recentes do fluxo. Essa configuração significa que suas regras podem avaliar as condições assim que novos dados chegarem.

## Abordagens alternativas de alerta

O mecanismo Activator também dá suporte à criação de alertas. Você pode criar alertas de painel diretamente de visualizações do painel em tempo real, configurar alertas de eventos do sistema para monitorar as atividades da área de trabalho do Fabric e as operações de arquivos do OneLake, ou criar alertas de consulta a partir de resultados e visualizações do conjunto de consultas KQL. Essas abordagens usam o mesmo mecanismo Activator, mas interpretam dados de forma diferente do modelo de objetos de negócios.
