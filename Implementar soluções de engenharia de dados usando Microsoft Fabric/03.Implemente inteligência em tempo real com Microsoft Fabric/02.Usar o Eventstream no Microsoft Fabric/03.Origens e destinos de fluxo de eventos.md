Depois de criar um fluxo de eventos no Fabric, você pode conectá-lo a uma ampla gama de fontes de dados, opcionalmente transformá-lo e rotear os dados transformados ou processados para vários destinos. Nesta unidade, examinaremos fontes e destinos de fluxo de eventos.

## Fontes Eventstream

Você pode transmitir dados de fontes da Microsoft e também ingerir dados de plataformas que não são da Microsoft, incluindo:

- **Fontes da Microsoft**, como Hubs de Eventos do Azure, Hubs IoT do Azure, Barramento de Serviço do Azure, CDC (Change Data Capture) alimentam serviços de banco de dados e outros.
- **Eventos do Azure**, como eventos do Armazenamento de Blobs do Azure.
- **Eventos do Fabric**, como alterações em itens em um workspace do Fabric, alterações de dados em armazenamentos de dados do OneLake e eventos relacionados a trabalhos no Fabric.
- **Fontes externas**, como Apache Kafka, Google Cloud Pub/Sub e MQTT (Transporte de Telemetria de Enfileiramento de Mensagens)

## Destinos de fluxo de eventos

Os dados de streaming exigem processamento e armazenamento imediatos para manter seu valor. Os destinos em um fluxo de eventos servem como pontos de extremidade em que os dados processados ficam disponíveis para consultas, relatórios, dashboards, alertas, ações ou integração com outros sistemas. Você pode carregar os dados do fluxo para os seguintes destinos:

- **Eventhouse**: esse destino permite ingerir seus dados de evento em tempo real em um Eventhouse, onde você pode usar a KQL (Linguagem de Consulta Kusto) para consultar e analisar os dados.
- **Lakehouse**: Este destino lhe dá a capacidade de transformar seus eventos em tempo real antes de ingeri-los em sua casa de lago. Os eventos em tempo real são convertidos no formato Delta Lake e, em seguida, armazenados em tabelas designadas do lakehouse.
- **Fluxo derivado**: você pode pensar em fluxos derivados como versões transformadas do fluxo de dados original que habilitam o **roteamento baseado em conteúdo**. Os fluxos derivados permitem rotear subconjuntos de dados do fluxo _padrão_ ou original para destinos diferentes com base no _conteúdo_ dos dados. Por exemplo, você pode filtrar dados do sensor de IoT para enviar alertas de alta temperatura para o Fabric Activator enquanto roteia as médias por hora para um banco de dados KQL.
- **Ativador do Fabric**: conecte diretamente seus dados de evento em tempo real a um mecanismo de detecção de eventos que dispara automaticamente ações quando padrões ou condições específicos são detectados em seus dados de streaming. Quando os dados atingem determinados limites ou correspondem a padrões, o Activator pode enviar notificações, iniciar fluxos de trabalho do Power Automate ou disparar outras respostas automatizadas.
- **Ponto de extremidade personalizado**: com esse destino, você pode rotear seus eventos em tempo real para um ponto de extremidade personalizado. Esse destino é útil quando você deseja direcionar dados em tempo real para um sistema externo ou aplicativo personalizado fora do Microsoft Fabric.

Você pode anexar a vários destinos em um fluxo de eventos ao mesmo tempo sem afetar ou colidir uns com os outros.

## Configurar destinos de fluxo de eventos

Os destinos eventstream podem ser configurados na tela eventstream. Um destino pode ser especificado depois que uma fonte de dados é conectada ou depois que transformações opcionais são aplicadas.

[![Captura de tela mostrando como configurar destinos na tela eventstream.](https://learn.microsoft.com/pt-br/training/wwl/explore-event-streams-microsoft-fabric/media/eventstream-destinations.png)](https://learn.microsoft.com/pt-br/training/wwl/explore-event-streams-microsoft-fabric/media/eventstream-destinations.png#lightbox)

A tela eventstream na imagem mostra:

- **Adicionar lista suspensa de destino**: para configurar novos destinos
- **Três destinos configurados**: um fluxo derivado, um Ativador do Fabric e um Eventhouse
- **Roteamento baseado em conteúdo**, onde a saída da transformação GroupByStreet é direcionada para um fluxo derivado que é então direcionado tanto para um Ativador, para verificar se há bicicletas em cada estação, quanto para um Eventhouse, para inserir contagens de bicicletas por rua em um banco de dados KQL.
